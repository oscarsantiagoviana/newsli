# Historical Worklog (R1 - R73c) - Offloading DLSS SR + NR to a Second GPU

Consolidated from: worklogs R18-R63 in poc-sr-offload-host/docs, wiki 01-15 of poc-dlss-standalone (05-historial covers R53-R73c), and the git history of both repos (81 + 37 commits). Testbed: 2x RTX 3060 12 GB (sm_86/Ampere, no native E4M3 tensor cores), driver 616.64, Windows 10 19044. Game: RDR2 2560x1080, DRS active, render ~853x360 (DLSS Performance x3). Fidelity reference = vendor eager fp32 path, bit-exact vs the NVIDIA DLL. Rounds without a written worklog (R1-R17, R24-R29, R47-R63 partial) are reconstructed from git and later references.

## Era R18-R46 - Anatomy of the NR vendor runtime on Ampere

- R18 (09-20) - ROOT CAUSE of the swimming: our ParamsBlock encoded floats x1000 (store = round(v*1000)); the snippet log showed MV.Scale 1.0 -> 1000.0 and jitter +-0.25 px -> +-250 px. Explained every earlier bench oddity (mv0 clean, MVAMP saturated, frame-reframing doses). Fix: params_block.h rewritten 1:1 with OptiScaler NVNGX_Parameter semantics. User verdict live: swimming solved; 1100+ frames stable. Green tiles + band remained.
- R19 - Alpha REFUTED as artifact cause: forcing alpha = 1.0 changes output alpha only (RGB bit-identical); the native 2022 DLL accumulates the same scratch alpha and the game looked fine. Delivered bytes contain no tile periodicity; the top band is a luminance gradient crossing the game tonemap threshold near x 2048. The live ALPHA1 probe had silently never run (Map on placed cross-adapter buffers always fails).

## Era R69-R73c - Offload host: real guides, delta compose, visible verification

- R69 - Real guides (depth + MV) into the vendor model (with stubs it was a 0.9995 identity). Seven crash sessions, four root causes: (1) WRL ComPtr operator& = ReleaseAndGetAddressOf released the lag guide EVERY frame (zero guides since day one); (2) done-wait blocking while holding ctx.cs when the producer hook also needs cs = 30 s game freeze => non-blocking delay-line; (3) recording guide barriers INSIDE the game list where native NGX records after evaluate corrupts the device minutes later (ERR_GFX_D3D_DEFERRED_MEM / EMP.dll / nvwgf2umx AV) => own command list submitted to the same DIRECT queue right AFTER the frame list (from the OnListSubmitted hook); (4) the game DSV seemed non-copyable (later corrected in R69v) => MV sealed for real (RT flag) + depth stub 0x5 in the engine. Final state: 3000+ frames ENHANCED @1707x720 ~50 ms, GPU1 99% / GPU2 97%, clean image.
- R69u - The delay-line that NEVER delivered (user: no watermark, no visible change): delivery required done >= pendingFrame while pendingFrame is overwritten every frame and the engine (50 ms) is slower than the game (16 ms) - mathematically impossible forever (live log: done 20023 < pending 53403, ratio 0.57). nrActive never rose, so the SR kept receiving the ORIGINAL color = perpetual eco. Fix: deliver when done > lastDeliveredDone. NR badge (8x8 px, HDR 512) visible for the FIRST time; 6700+ frames, FPS 51. Lessons: compare against last DELIVERED, not last REQUESTED; processing != delivery - verify the last link with a deliberate visual mark.

## Standing decisions and rules (user-mandated, enforced throughout)

- No legacy / no retro-compatibility in POCs: dead code is DELETED from the tree (recover from git if ever needed).
- Structural fixes only: what is necessary becomes THE code path, never a config option.
- A/B before accepting any hypothesis; validate in game, not only in sim; measure in the regime where the user sees the problem (the daytime A/B poisoned the night-grain case).
- Read the reference (fork) and the whole project file-by-file BEFORE theorizing; references-vs-our-code comparison BEFORE the first hypothesis (5 avoidable crashes in R69v).
- Kill processes ALWAYS by PID, never by /IM; check for zombie runners after every sim/bench (they inflate later timings).
- Deliver inside the game command list (in-list) - out-of-band delivery was the stripes bug (R21).
- Reset-before-recording is per BLOCK (R63b); the SR socket always gets a fresh list (R60).
- Panel: all arrays and initializers grow together with NPARAMS; NR knobs always-value, game params override-only (R72).
- Verification needs a deliberate visual mark per pipeline step (badge, later delta-tint), and screen captures are valid ONLY via CopyFromScreen in borderless (R70e).
- Processing != delivery: explicitly verify the LAST link (R69u); a delay-line delivers against last-delivered, never against last-requested.
